# 島嶼市長：系統設計文件（SDD）

版本：0.1｜狀態：規劃草案｜日期：2026-10-28

本設計支援 [PRD](PRD.md)。參考網站目前因網路代理 403 無法檢視；具體畫面、事件、資源與語音數量須在盤點後補齊。本文件描述預定架構，不表示功能已實作或測試。

## 1. 架構與技術選擇

採用 React、TypeScript、Vite 與 CSS design tokens；使用 Zustand 管理遊戲狀態，Motion 處理動態，Howler.js 管理預製音訊。具體依賴及版本在實作時固定於 lockfile。應用建置成靜態資產，可部署到 Cloudflare Workers 或 Pages；不建立應用後端、帳號或資料庫。

```text
靜態內容 / 圖像 / 音檔
          ↓
內容載入 → 遊戲狀態與規則 → 畫面與互動
                   ↕              ↕
             本機存檔          音訊控制器
```

建議目錄：`src/app`（入口與路由）、`src/components`（共用元件）、`src/features`（畫面與流程）、`src/game`（規則與狀態）、`src/content`（資料）、`src/audio`（播放控制）、`src/styles`（tokens）、`public/assets`（素材）、`tests`（驗證）。具體 feature 名稱依盤點結果建立。

## 2. 內容、狀態與規則

以具型別的靜態資料定義場景、對話、選項、結果與素材引用；穩定 ID 用於關聯、存檔與測試。規則應以純函式計算狀態轉移，使選項結果可獨立驗證；UI 不直接修改資料。盤點後定義完整狀態圖及各分支，不預設參考站的遊戲數值。

建議存檔結構：`schemaVersion`、遊戲進度、設定與更新時間。僅在有效狀態變更後保存至 `localStorage`；讀取時驗證版本與內容，未來版本提供明確遷移策略。損壞、空間不足或儲存被停用時，顯示可理解的提示並允許繼續使用記憶體狀態；重置須先確認。避免儲存敏感資訊。

## 3. 介面與音訊

建立色彩、字型、間距、尺寸、陰影及動態 tokens；共用元件包含按鈕、對話框、卡片、控制列及提示。使用語意化 HTML、鍵盤操作、焦點管理、適當的 accessible name 和螢幕閱讀器狀態提示。對話框開啟時管理焦點，關閉後回到觸發元素。支援 `prefers-reduced-motion`，使動畫減少時流程與資訊仍完整。

音訊控制器分離語音、音樂與 UI 音效，維護各自音量和靜音狀態；使用者首次互動後才解鎖播放。每個語音 cue 以 ID 對應音檔、台詞、角色及字幕；切換場景或跳過時停止過期語音，避免重疊。載入或播放失敗時保留字幕與操作，顯示適當提示。按需預載常用音檔並使用可在目標瀏覽器播放的格式；正式素材須驗證授權、發音、品質及檔案大小。

## 4. 部署與運行

建置輸出為靜態檔，使用套件管理器的鎖定版本安裝並執行開發、建置與預覽命令。詳細命令與部署配置待專案建立後記錄於 README，並在實際環境驗證。所有遊戲內容隨版本發布；無伺服器保存或遠端帳號依賴。離線使用僅保證已載入的資源；完整離線支援需另行設計與驗收。

## 5. 測試與驗證

| 類別 | 驗證內容 |
| --- | --- |
| 單元 | 規則轉移、存檔驗證／遷移、音量與 cue 選擇；測試有效及無效輸入 |
| 整合 | 完成主要流程、返回與重置、重載恢復、儲存失敗及音訊失敗 |
| 瀏覽器 | Chrome、Firefox、Safari／行動瀏覽器的主要流程；記錄實際版本與未測項目 |
| 視覺 | 依盤點表比較參考站及 390、768、1440px 畫面，人工審核裁切與狀態 |
| 無障礙 | 鍵盤、焦點、字幕、對比與減少動態，輔以自動檢查 |
| 音訊 | 人工聆聽各角色、字幕同步、音量、跳過、重播及瀏覽器首次互動限制 |
| 效能 | 記錄測量設備、網路、LCP、CLS、資產大小及載入失敗處理 |

## 6. 實作順序與決策關卡

1. 取得參考站存取，建立畫面／狀態／互動／音訊清單，更新 PRD 驗收矩陣及此設計。
2. 建立工具鏈、design tokens 與基礎元件；先完成可播放語音的代表性垂直切片。
3. 擴充已確認的主要流程、內容與本機存檔，補齊合法授權素材。
4. 執行上述測試並逐項記錄差異與限制；部署前驗證正式建置。

未取得參考站與素材前，不應宣稱達成一模一樣、完整功能或高水準配音。技術與元件選型可依盤點結果調整，但須保留靜態執行、無登入及無資料庫的約束。
